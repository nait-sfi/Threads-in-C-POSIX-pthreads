01

What is a thread?

A thread is the smallest unit of execution scheduled by the operating system. Every process has at least one thread (the main thread). Additional threads share the same virtual address space — the same code, heap, and global variables — but each has its own stack, program counter, and register set.

Each thread owns its stack + PC + registers · All threads share code, heap, globals

Threads vs Processes

A new process gets a full copy of the address space (expensive — fork() uses copy-on-write). A new thread shares the existing address space, making creation and context-switching much cheaper.

Why use threads?

Parallelism on multi-core CPUs, responsive UIs (background work while main thread listens), I/O concurrency (one thread blocks on disk, others run), and simpler structure than event-loop callbacks.

02

Under the hood

On Linux, pthread_create() ultimately calls the clone() syscall — the same syscall used by fork(), but with flags that tell the kernel to share the address space, file descriptors, and signal handlers instead of copying them.

What the kernel does when you create a thread

pthread_create() → glibc wrapper → clone() syscall → kernel: new task_struct → scheduler picks it up

The kernel creates a new task_struct (same structure it uses for processes). The new thread gets its own kernel stack, its own stack in user space (typically 8 MB, allocated by pthreads), and a Thread Control Block (TCB) that stores its ID, stack pointer, and attributes.

Scheduling

The OS scheduler treats each thread as an independent unit. On a multi-core machine, two threads from the same process can literally run simultaneously on different cores. On a single core they interleave — the scheduler preempts one thread and resumes another based on time slices.

Context switching

When the scheduler switches between threads, it saves the current thread's registers (including the program counter and stack pointer) into its TCB, then loads the next thread's saved state. This is why each thread needs its own registers and stack.

The scheduler is non-deterministic. You cannot predict the exact order threads will execute. Two runs of the same program can interleave differently. This is the root cause of race conditions and why synchronization exists.

03

Thread creation

POSIX threads are created with pthread_create(). You pass it a function pointer — the thread routine — and the thread begins executing that function concurrently.

pthread_create
creation
int pthread_create(pthread_t *thread, const pthread_attr_t *attr, void *(*start)(void *), void *arg)

Creates a new thread. The new thread starts executing start(arg) immediately (subject to the scheduler). The calling thread continues without waiting.


thread — output: the OS fills in the thread ID here.
attr — thread attributes (stack size, detach state…). Pass NULL for defaults.
start — the function the new thread runs. Must have signature void *(void *).
arg — a single pointer passed to start. Cast to whatever you need.

Returns 0 on success · errno code on failure (EAGAIN, ENOMEM, EINVAL…)
basic_thread.cC
#include <pthread.h>
#include <stdio.h>

// Thread routine — must match void *(void *) signature
void    *thread_routine(void *arg)
{
    int  id = *(int *)arg;  // cast the generic pointer back
    printf("[Thread %d] running\n", id);
    return (NULL);
}

int     main(void)
{
    pthread_t  tid;
    int        id = 42;

    // Create the thread — starts immediately
    if (pthread_create(&tid, NULL, thread_routine, &id) != 0)
    {
        perror("pthread_create");
        return (1);
    }

    // Wait for thread to finish before exiting
    pthread_join(tid, NULL);
    printf("[Main] done\n");
    return (0);
}
The void * trick. Because pthread_create accepts only one argument to the thread function, you typically pass a pointer to a struct that contains all the data the thread needs. Always make sure that memory outlives the thread — never pass a pointer to a stack variable that might be freed before the thread uses it.
pthread_join
blocking wait
int pthread_join(pthread_t thread, void **retval)
Blocks the calling thread until thread finishes. Reclaims its resources. retval receives the value returned by the thread routine (pass NULL to ignore).
Returns 0 on success
pthread_detach
fire & forget
int pthread_detach(pthread_t thread)
Marks the thread as detached — its resources are released automatically when it finishes. You can no longer join it. Use when you don't need the return value and don't want to track the thread.
Returns 0 on success
Always join or detach every thread. A thread that is neither joined nor detached is a zombie thread — its resources are never freed. If your process creates many threads without joining them, you'll leak memory and eventually hit the system thread limit.
04

Thread lifecycle

NEW

pthread_create() was called. The kernel has created the task but the scheduler hasn't given it CPU time yet.

RUNNABLE

Ready to run, waiting for the scheduler to assign it a CPU core. May bounce between runnable and running many times.

RUNNING

Actually executing on a CPU core. The scheduler may preempt it at any moment (end of time slice, higher-priority thread wakes up).

BLOCKED

Waiting for something — a mutex lock, a condition variable, I/O completion. Not using any CPU. Woken up by the event it's waiting for.

TERMINATED

The thread routine returned or pthread_exit() was called. Resources are freed only after pthread_join() or if it was detached.

05

Race conditions

A race condition happens when two or more threads access shared mutable data concurrently, and the result depends on the exact timing of their execution. The result is undefined behavior — sometimes it looks correct, which makes bugs nearly impossible to reproduce.

race_example.c — BROKENC
int  counter = 0;  // shared global

void  *increment(void *arg)
{
    for (int i = 0; i < 1000000; i++)
        counter++;  // NOT atomic — this is 3 CPU instructions!
    return (NULL);
}
// Expected: counter == 2000000
// Actual:   counter == 1387234  ← different every run
counter++ is NOT atomic. At the machine level it compiles to three instructions: LOAD (read counter into register), ADD (increment register), STORE (write back). The scheduler can interrupt between any of these, causing lost updates.

What "lost update" looks like

⚠ Without mutex — race condition
counter=5
Thread 1LOAD → reg=5
Thread 2LOAD → reg=5
Thread 1ADD → reg=6
Thread 1STORE → counter=6
Thread 2ADD → reg=6
Thread 2STORE → counter=6 ✗
Lost one increment — should be 7
✓ With mutex — safe
counter=5
Thread 1LOCK mutex
Thread 1LOAD → reg=5
Thread 1ADD → reg=6
Thread 1STORE → counter=6
Thread 1UNLOCK mutex
Thread 2LOCK mutex
Thread 2LOAD → 6, STORE → 7 ✓
06

Mutexes

A mutex (mutual exclusion lock) is the primary tool for protecting shared data. Only one thread can hold a mutex at a time. Any other thread that tries to lock it will block until the holder unlocks it.

Under the hood — how a mutex works

A mutex is essentially an atomic flag in memory. The CPU provides atomic test-and-set instructions (like CMPXCHG on x86) that can check and set a value in a single, uninterruptible operation. When you call pthread_mutex_lock():

try atomic set → if free: lock it · continue → if taken: spin briefly → then: syscall · block · sleep → wake on unlock

Modern mutexes are futexes (fast userspace mutexes) on Linux. They avoid the expensive kernel syscall in the uncontested case — the lock/unlock is just an atomic memory operation when no other thread is waiting.

pthread_mutex_init
init
int pthread_mutex_init(pthread_mutex_t *mutex, const pthread_mutexattr_t *attr)
Initializes a mutex. Pass NULL for attr to get a default (fast, non-recursive) mutex. Alternatively, use the static initializer PTHREAD_MUTEX_INITIALIZER for global mutexes.
Returns 0 on success
pthread_mutex_destroy
cleanup
int pthread_mutex_destroy(pthread_mutex_t *mutex)
Releases resources held by the mutex. Must be called when the mutex is no longer needed. The mutex must be unlocked before destroying it, otherwise behavior is undefined.
Returns 0 on success
pthread_mutex_lock
blocking lock
int pthread_mutex_lock(pthread_mutex_t *mutex)
Acquires the mutex. If the mutex is already locked by another thread, the calling thread blocks (sleeps) until it becomes available. A thread must never lock a mutex it already holds — that's a deadlock.
Returns 0 on success
pthread_mutex_unlock
release
int pthread_mutex_unlock(pthread_mutex_t *mutex)
Releases the mutex. If other threads are blocked waiting for it, one of them is woken up and given the lock. Only the thread that locked the mutex should unlock it.
Returns 0 on success
pthread_mutex_trylock
non-blocking
int pthread_mutex_trylock(pthread_mutex_t *mutex)
Tries to acquire the mutex without blocking. If the mutex is locked, it returns immediately with EBUSY instead of sleeping. Useful to avoid deadlocks or to do other work while waiting.
Returns 0 if locked · EBUSY if taken
mutex_example.c — fixed race conditionC
#include <pthread.h>
#include <stdio.h>

int             counter = 0;
pthread_mutex_t lock;     // the mutex — one per shared resource

void  *increment(void *arg)
{
    for (int i = 0; i < 1000000; i++)
    {
        pthread_mutex_lock(&lock);    // ← enter critical section
        counter++;                      // safe: only one thread here at a time
        pthread_mutex_unlock(&lock);  // ← exit critical section
    }
    return (NULL);
}

int   main(void)
{
    pthread_t  t1, t2;

    pthread_mutex_init(&lock, NULL);  // initialize before any thread uses it

    pthread_create(&t1, NULL, increment, NULL);
    pthread_create(&t2, NULL, increment, NULL);

    pthread_join(t1, NULL);
    pthread_join(t2, NULL);

    printf("counter = %d\n", counter);  // always 2000000

    pthread_mutex_destroy(&lock);     // clean up
    return (0);
}

Deadlocks

A deadlock occurs when two or more threads are each waiting for a lock held by the other — they all block forever. Classic example:

⚠ Deadlock scenario
Thread 1: lock(A) → tries lock(B) → 🔴 blocked
Thread 2: lock(B) → tries lock(A) → 🔴 blocked
Neither can proceed. Forever.
✓ Prevention: consistent order
Thread 1: lock(A) → lock(B) → unlock(B) → unlock(A)
Thread 2: lock(A) → lock(B) → unlock(B) → unlock(A)
Always lock in the same order.
Rules to avoid deadlocks: always acquire multiple locks in the same global order · keep critical sections as short as possible · never call unknown functions while holding a lock · consider using pthread_mutex_trylock with backoff for complex scenarios.

08

Common patterns

Pattern 1 — Passing data to a thread via struct

thread_args.cC
typedef struct s_args {
    int     id;
    int     *shared_counter;
    pthread_mutex_t *lock;
} t_args;

void  *worker(void *arg)
{
    t_args  *a = (t_args *)arg;

    pthread_mutex_lock(a->lock);
    (*a->shared_counter)++;
    printf("Thread %d incremented counter to %d\n", a->id, *a->shared_counter);
    pthread_mutex_unlock(a->lock);
    return (NULL);
}

int   main(void)
{
    pthread_t       threads[4];
    t_args          args[4];
    pthread_mutex_t lock;
    int             counter = 0;

    pthread_mutex_init(&lock, NULL);
    for (int i = 0; i < 4; i++) {
        args[i] = (t_args){i, &counter, &lock};
        pthread_create(&threads[i], NULL, worker, &args[i]);
    }
    for (int i = 0; i < 4; i++)
        pthread_join(threads[i], NULL);
    pthread_mutex_destroy(&lock);
    return (0);
}

Pattern 2 — Thread pool (create once, reuse)

Creating and destroying threads has overhead. For repeated short tasks, create a fixed pool of threads once, feed them work via a shared queue (protected by a mutex), and keep them alive for the program's lifetime. This avoids repeated pthread_create costs.

Compile & link

terminalbash
gcc -Wall -Wextra -pthread your_file.c -o your_program
# -pthread sets the right defines AND links libpthread
# On some systems: -lpthread instead of -pthread

Full example — threads + mutex

threads_full.cC
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>

#define NUM_THREADS  5
#define INCREMENTS   100000

/* ── Shared state ──────────────────────────────── */
typedef struct s_shared {
    int             counter;
    pthread_mutex_t lock;
} t_shared;

/* ── Thread argument ───────────────────────────── */
typedef struct s_args {
    int         id;
    t_shared    *shared;
} t_args;

/* ── Thread routine ────────────────────────────── */
void  *worker(void *arg)
{
    t_args  *a = (t_args *)arg;

    for (int i = 0; i < INCREMENTS; i++)
    {
        pthread_mutex_lock(&a->shared->lock);
        a->shared->counter++;
        pthread_mutex_unlock(&a->shared->lock);
    }
    printf("[Thread %d] done\n", a->id);
    return (NULL);
}

/* ── Main ──────────────────────────────────────── */
int   main(void)
{
    pthread_t  threads[NUM_THREADS];
    t_args     args[NUM_THREADS];
    t_shared   shared;

    // Init shared state
    shared.counter = 0;
    pthread_mutex_init(&shared.lock, NULL);

    // Launch all threads
    for (int i = 0; i < NUM_THREADS; i++)
    {
        args[i].id     = i;
        args[i].shared = &shared;
        if (pthread_create(&threads[i], NULL, worker, &args[i]) != 0)
        {
            perror("pthread_create");
            return (1);
        }
    }

    // Wait for all threads to finish
    for (int i = 0; i < NUM_THREADS; i++)
        pthread_join(threads[i], NULL);

    printf("Final counter: %d (expected %d)\n",
        shared.counter, NUM_THREADS * INCREMENTS);

    pthread_mutex_destroy(&shared.lock);
    return (0);
}
